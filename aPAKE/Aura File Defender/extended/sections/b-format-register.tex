\section{Canonical Format Register}\label{app:format-register}

This appendix records the implemented output profiles against which the
methods in Section~\ref{sec:format-methods} are interpreted.  A registry entry
does not state an empirical success rate.  It states the accepted output
language, reconstruction level, retained semantic boundary, and strongest
claim that follows from implementation inspection.  The registry version in
the Rust validator is \texttt{aura-canonical-registry-v1}.  MIME aliases in the
table select one parser profile.  They do not create additional grammars.

\subsection{Static raster register notes}

BMP and TIFF are decodeable input classes in the semantic image path but are
not canonical output profiles.  Their accepted outputs are newly encoded PNG,
JPEG, or static WebP according to policy.  Static PNG explicitly forbids APNG
chunks.  Static WebP explicitly forbids animation chunks.  These distinctions
matter because a broad label such as ``image'' is not a release grammar.
Raster validation combines a structural parser with a second bounded decode.
The current validation decode permits at most 30 million pixels.  This fixed
validator bound applies in addition to the handler's policy-bound probe and
post-decode checks.

The metadata policy for semantic rasters is exclusion by reconstruction.  The
intermediate image object carries decoded pixels rather than source EXIF, XMP,
ICC, comments, thumbnails, or application records.  The output parser then
verifies that the emitted grammar contains no component through which those
classes could remain.  This is a structural absence claim.  It is not a claim
that no pixel pattern can encode private or executable information under some
external interpretation.

\subsection{Animated image register notes}

GIF, APNG, and animated WebP occupy different reconstruction levels despite all
representing animation.  GIF frames are decoded and re-encoded.  The GIF method also
normalizes delays below two centiseconds and enforces an aggregate decoded
pixel budget. The fixed duration threshold of 6000 centiseconds applies to one
animation cycle. It does not bound total viewing time for an indefinite loop.
The registered semantic state therefore includes documented timing
normalization, and exact second-pass byte equality is not expected.

APNG is a constrained PNG chunk language.  The current path validates and
remuxes complete chunks but retains compressed frame data.  Required palette
and transparency chunks are preserved only when compatible with IHDR.  All
other ancillary chunks are outside the output allowlist.  A successful
\texttt{apng-canonical-v1} report does not upgrade the performed level from
$\Structural$ to $\Semantic$.  Under a semantic-or-block policy, the correct
outcome remains blocking even when the candidate APNG is structurally
canonical.

Animated WebP is a constrained RIFF chunk language.  The handler removes
\texttt{ICCP}, \texttt{EXIF}, and \texttt{XMP }, rewrites the outer length and
feature bits, and retains bounded \texttt{ANMF} frame payloads.  The independent
validator reparses the entire chunk hierarchy and decodes every frame to check
canvas, dimensions, alpha state, frame count, and pixel budgets.  Decoder
success is an additional postcondition, not evidence that source frame payloads
were regenerated.  The reported reconstruction level therefore remains
$\Structural$, and a semantic-or-block policy does not release this candidate.

\subsection{Audio register notes}

The MP3 profile starts at the first retained MPEG frame and ends at the exact
end of the last frame.  ID3v2 and ID3v1 can be removed by the handler, but the
canonical output grammar admits neither.  Frame length is calculated from
version, layer, bitrate, sample rate, and padding rather than by searching for
the next sync pattern.  This prevents an incidental sync-like byte sequence
inside a frame from defining the structural boundary.

The WAV profile is limited to integer PCM with a 16-byte \texttt{fmt } body.
Compressed WAV variants, extensible format records, and arbitrary ancillary
chunks are not part of this entry.  Odd payload length is represented by one
generated zero byte.  The pad is included in the outer RIFF size but excluded
from the \texttt{data} chunk's declared sample length.

FLAC receives a structural claim despite deep frame parsing.  Parsing a
predictor and residual grammar to a checksum-valid frame boundary is not the
same operation as decoding samples and creating new frames.  The validator
does not recompute STREAMINFO MD5 from uncompressed samples.  This distinction
prevents checksum verification from being misreported as semantic
reconstruction.

The Ogg entry covers Opus and Vorbis only.  It does not cover chained logical
streams, multiplexed serial numbers, foreign codecs, or arbitrary comment
repagination.  The handler's current safe replacement case is a complete
single-page comment packet that shares no page with another packet.  More
general layouts fail closed.  The independent validator can reconstruct packet
boundaries across pages, but that broader validation ability does not imply a
broader rewriting implementation.

\subsection{Container register notes}

The ISO BMFF entry is intentionally nonfragmented and uses one permitted
\texttt{mdat} extent.  Fragment tables and general multi-extent relocation are
not registered.  A box name is not globally safe.  Acceptance depends on the
box's parent, order, multiplicity, version, and relationship with other tables.
The validator therefore combines parent-specific closure with cross-table
sample accounting. Derived sample extents from all tracks must cover the single
\texttt{mdat} payload exactly without a gap or overlap. MOV and M4A are input naming or branding contexts. The
registered outputs are selected as \texttt{video/mp4} or \texttt{audio/mp4}
after track proof.  Apple-originated \texttt{audio/m4a} and
\texttt{audio/x-m4a} values are routing aliases for the latter.  The structural
profile removes nonessential advisory and legacy atoms, including sample-group,
sample-dependency, partial-sync, composition-shift, object-descriptor,
extended-language, and track-reference records.  Canonical visual sample
entries may retain \texttt{fiel} and \texttt{chrm} only when their values and
lengths satisfy the constrained validator.

The EBML implementation registers WebM, not unrestricted Matroska.  A
\texttt{DocType=matroska} input bypasses the native WebM rewriter and can enter
the supervised semantic transcoder when policy requires and permits that path.
It never inherits the WebM structural claim merely because both formats use
EBML.  The WebM
profile permits one video track using VP8, VP9, or AV1 and at most one Opus
track.  Subtitle, metadata, and attachment tracks are excluded.  Unknown-size
encoding is accepted only for the root Segment, where EOF supplies the bound.
SimpleBlock lacing is parsed to complete frame extents, while video lacing is
excluded.  SeekHead, Cues, Position, PrevSize, and related stale-location
structures are removed rather than copied after layout changes.

\subsection{Unsupported classes and release interpretation}

No canonical output entry exists for PDF, Office documents, archives,
executables, scripts, vector markup, packages, shortcuts, or unknown binary
formats.  Detection of a familiar prefix, extension, or MIME string does not
promote one of these classes to support.  Adding support would require a new
output grammar, reconstruction-level decision, metadata policy, complete
parser, post-reconstruction validator, resource model, and evidence plan.

The register also does not list AAC as an assigned format method, although the
codebase contains an ADTS output validator.  This appendix is scoped to the
families specified for the present manuscript contribution and does not infer
a complete reconstruction claim from validator registration alone.  In all
entries, a canonical report remains necessary but insufficient for
publication.  The performed level must satisfy policy, post-reconstruction
checks must pass, and the release result must contain no blocking condition.
Measured robustness, compatibility, fidelity, and performance remain deferred
to the controlled server run.
